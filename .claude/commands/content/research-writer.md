# コンテンツリサーチ＆ライティングスキル

指定されたトピックについてリサーチを行い、高品質なコンテンツを作成します。

## 使用方法
```
/content:research-writer <トピック> [--type=<コンテンツタイプ>] [--audience=<対象読者>] [--length=<長さ>]
```

---

## When to Use

- 技術ブログ記事の執筆
- ドキュメント・ガイドの作成
- 比較記事・レビューの作成
- チュートリアル・ハウツーの作成
- ホワイトペーパー・技術レポートの作成

## Scope

| コンテンツタイプ | 説明 | 目安文字数 |
|-----------------|------|-----------|
| blog | ブログ記事 | 2,000-4,000字 |
| tutorial | チュートリアル | 3,000-6,000字 |
| guide | 包括的ガイド | 5,000-10,000字 |
| comparison | 比較記事 | 2,000-4,000字 |
| whitepaper | ホワイトペーパー | 5,000-15,000字 |
| documentation | 技術ドキュメント | 可変 |

## Step 2: OUTLINE（構成）

### 標準的な構成パターン

#### ブログ記事

```markdown
1. 導入（フック + 記事の概要）
2. 背景・なぜ重要か
3. 本論
   - ポイント1
   - ポイント2
   - ポイント3
4. 実践的なヒント
5. まとめ + CTA
```

#### チュートリアル

```markdown
1. はじめに（ゴールと前提条件）
2. 環境構築
3. ステップ1: 基本設定
4. ステップ2: 実装
5. ステップ3: 動作確認
6. トラブルシューティング
7. 次のステップ
```

#### 比較記事

```markdown
1. 概要（比較の目的）
2. 評価基準
3. 選択肢A: 詳細分析
4. 選択肢B: 詳細分析
5. 選択肢C: 詳細分析
6. 比較表
7. ユースケース別推奨
8. 結論
```

#### ガイド

```markdown
1. エグゼクティブサマリー
2. 対象読者と前提知識
3. 基礎概念
4. 詳細解説
   - セクション1
   - セクション2
   - セクション3
5. 実践ガイド
6. よくある質問
7. リソース・参考文献
```

## Step 3: DRAFT（執筆）

### 執筆ガイドライン

```
┌─────────────────────────────────────────────────────────┐
│                    執筆の原則                            │
└─────────────────────────────────────────────────────────┘

1. 明確さ > 華麗さ
   → シンプルで直接的な表現を優先

2. 具体性 > 抽象性
   → 具体例・コード・図を積極的に使用

3. 読者視点 > 著者視点
   → 読者が知りたいことを優先

4. 構造化 > 散文
   → 見出し・箇条書き・表を活用
```

### セクション別のテンプレート

#### 導入部（リード文）

```markdown
[問題提起/興味を引くフック]

この記事では、[トピック]について解説します。
読み終わる頃には、以下のことがわかるようになります：

- [学べること1]
- [学べること2]
- [学べること3]

対象読者: [前提知識/経験レベル]
```

#### 本文セクション

```markdown
## [セクションタイトル]

[導入: このセクションで何を説明するか]

### [サブトピック1]

[説明文]

```code
// 具体的なコード例
```

### [サブトピック2]

[説明文]

> **ポイント:** [重要な補足情報]

| 項目 | 説明 |
|-----|------|
| A | ... |
| B | ... |
```

```markdown

- [ポイント3]

- [推奨アクション1]

## Step 4: POLISH（仕上げ）

### チェックリスト

```markdown
## 内容チェック
- [ ] 論理的な流れ・一貫性
- [ ] 情報の正確性
- [ ] 過不足のない説明
- [ ] 具体例の適切さ

## 読みやすさチェック
- [ ] 適切な見出し構造
- [ ] 段落の長さ（3-5文程度）
- [ ] 箇条書きの活用
- [ ] 視覚的な要素（図・表・コード）

## 技術的チェック
- [ ] コードの動作確認
- [ ] コマンドの正確性
- [ ] バージョン情報の記載
- [ ] リンクの有効性

## SEO・アクセシビリティ
- [ ] タイトルの最適化
- [ ] メタディスクリプション
- [ ] 画像のalt属性
- [ ] 内部/外部リンク
```

### 改善ポイント

```
【冗長表現の修正】
❌ 「〜することができます」 → ⭕ 「〜できます」
❌ 「〜という形になります」 → ⭕ 「〜です」
❌ 「基本的には」「本質的には」 → 削除または具体化

【具体化】
❌ 「パフォーマンスが向上します」
⭕ 「レスポンス時間が約40%短縮されます」

【能動態の使用】
❌ 「このファイルが作成されます」
⭕ 「このコマンドでファイルを作成します」
```

## オプション

| オプション | 説明 | 例 |
|-----------|------|-----|
| `--type` | コンテンツタイプ | `--type=tutorial` |
| `--audience` | 対象読者 | `--audience=beginner` |
| `--length` | 目安の長さ | `--length=long` |
| `--language` | 言語 | `--language=ja` |
| `--tone` | トーン | `--tone=formal` |
| `--format` | 出力形式 | `--format=markdown` |

### 対象読者レベル

| レベル | 説明 |
|-------|------|
| `beginner` | 初心者・未経験者 |
| `intermediate` | 中級者・実務経験あり |
| `advanced` | 上級者・専門家 |
| `mixed` | 幅広い層向け |

### 長さ

| 長さ | 目安文字数 |
|-----|-----------|
| `short` | 1,000-2,000字 |
| `medium` | 2,000-4,000字 |
| `long` | 4,000-8,000字 |
| `comprehensive` | 8,000字以上 |
